Temporally Adaptive Sorting for Gaussian Splatting

Project proposal

Summary

In our project, we aim to speed up 3D Gaussian Splatting for smoothly moving cameras without introducing visible popping artifacts. Building on the work StopThePop, we propose to use information from nearby camera frames to adaptively determine which image regions require accurate hierarchical sorting and which can use a cheaper sorting method.

Problem description

In augmented and virtual reality, virtual tours, and robotic teleoperation, users often need to smoothly navigate through reconstructed 3D scenes, which requires rendering a sequence of images from continuously changing camera viewpoints. 3D Gaussian Splatting (3DGS) enables real-time novel-view rendering, but requires sorting Gaussians by depth at each frame. Repeating this sorting process can introduce redundant computation, especially when the camera moves only slightly. Moreover, standard 3DGS approximates Gaussian depth using the center of each Gaussian. This can lead to incorrect blending orders that change abruptly as the camera moves, producing visible popping artifacts and reducing temporal consistency.

Recent work has addressed these two challenges separately. Neo, for instance, reuses previously sorted Gaussian lists across consecutive frames to reduce computation. However, it retains the approximate depth ordering of standard 3DGS and therefore is still prone to popping artifacts. StopThePop, on the other hand, introduces a more accurate hierarchical per-pixel sorting scheme to reduce popping artifacts, but processes each frame independently.

Motivated by these works, our goal is to investigate whether we can combine the advantages of both approaches. Intuitively, if we run StopThePop's accurate hierarchical sorting at frame t, and the camera moves only slightly in the next frame, we expect the sorting requirements to remain similar. We can therefore use information from the previous frame to adaptively determine which image regions require accurate hierarchical sorting and which can use a cheaper sorting method.

Goals and deliverables

Our approach is to avoid performing StopThePop's hierarchical sorting independently for every frame. Below is an overview of our proposed method.

  • Frame t: Run StopThePop's hierarchical sorting algorithm. For each image patch, we estimate its sorting difficulty by comparing the initial approximate Gaussian ordering with the final per-pixel ordering, using a metric such as inversion rate.
  • Frame t+1: We reuse the previous frame's patch-level difficulty scores to predict which regions require accurate sorting. In particular, for patches with low sorting difficulty, we use the simpler Gaussian center-depth sorting from standard 3DGS, while for patches with high sorting difficulty, we apply StopThePop's full hierarchical sorting.
  • Periodic updates: We periodically run full hierarchical sorting to refresh the difficulty scores, especially after significant camera movements.

What we plan to deliver

  • A working prototype with per-tile selection between cheap sorting and StopThePop's hierarchy, tested on pretrained scenes and smooth camera paths.
  • Side-by-side camera fly-throughs and heatmaps showing where accurate sorting is selected.
  • We will compare the rendering time and image quality of our method against standard 3DGS and StopThePop. We will also measure the rendering time of both the cheap and accurate sorting paths to determine whether adaptive sorting provides meaningful speedups.

What we hope to deliver

  • A polished interactive viewer with a quality threshold slider and live performance statistics.
